## 三条贯穿性叙事（面试官追问时用）

### 1. "闭环"体现在哪
评估结果回流调参：分块大小/overlap、检索阈值、RRF k 值、是否开 Query Rewrite/HyDE——**每一环的输出都是下一环的输入，最后一环（评估）又回头调第一环（预处理）**。

### 2. "防幻觉"体现在哪（工程成熟度信号）
- 检索侧：阈值 → 未找到就明说（不硬答）
- 生成侧：prompt 强约束 + Faithfulness 后端评估（双防线）
- 数据侧：证据事实字段全部取自服务端检索结果，模型只能选不能编（上一轮证据闭环）

### 3. "可扩展性"体现在哪（架构判断力）
- 解析器、分块策略、检索策略、查询预处理、证据布局——**全部策略接口**，新方案=新实现类，调用方不动
- 加文档=改 `sources.yml`，不加代码（数据驱动）

## 面试防翻车点（最容易答砸的细节）

| 坑 | 正确答法 |
|---|---|
| RRF 公式记不住 | 写 `score(d)=Σ 1/(k+rank)`，k 常取 60；当场手算一个例子 |
| 把 BM25 说成 Postgres 原生 | 说"Postgres FTS 的 ts_rank 是 BM25 的近似"，别吹成真 BM25 |
| HyDE 只讲优点 | 必须讲代价：假设答案可能带偏检索，适合短问题 |
| 说"我用了 RAGAS"但没落地 | 说"概念用 LLM-as-judge 在 Java 端简化实现"，诚实区分 |
| MTEB 当圣旨 | "MTEB 是参考，必须自有数据集 Recall@K 验证" |
| overlap 只讲好处 | 讲代价：索引膨胀、结果可能重复 |
